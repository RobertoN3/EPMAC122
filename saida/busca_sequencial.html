Problema
Dado um vetor não ordenado com n elementos e um valor x, decidir se x está no vetor e em que posição ele aparece pela primeira vez

Ideia geral

Procurar um valor em uma coleção é uma das tarefas mais comuns em programação: um nome numa agenda, um produto num estoque, uma palavra num texto. Quando os dados estão em um vetor sem nenhuma ordem, não há atalho: a única maneira de ter certeza de que x não está no vetor é olhar todos os elementos. A busca sequencial (ou busca linear) faz exatamente isso: examina v[0], v[1], v[2], ..., até encontrar x ou chegar ao fim do vetor.

Esta página trata da busca em vetor NÃO ordenado. Se o vetor estiver ordenado, a busca binária é muito mais rápida.

O algoritmo

  busca(v, n, x):
      j <- 0
      enquanto j < n:
          se v[j] == x: devolva j      (primeira ocorrência)
          j <- j + 1
      devolva -1                       (x não está no vetor)

Convenção usada no material da disciplina: a função devolve o índice da primeira ocorrência de x, ou -1 se x não ocorre. Como todo índice válido é maior ou igual a zero, o valor -1 não pode ser confundido com uma posição.

Por que está correto: o invariante

No início de cada iteração do laço vale o invariante:

  x não pertence a v[0..j-1]
  • No início, j = 0 e o trecho v[0..-1] é vazio: o invariante vale.
  • Se o invariante vale e v[j] != x, então x também não está em v[0..j]; ao fazer j <- j + 1, ele continua valendo.
  • Se o laço devolve j, é porque v[j] == x e, pelo invariante, nenhuma posição anterior tem x: j é de fato a PRIMEIRA ocorrência.
  • Se o laço termina com j == n, o invariante diz que x não está em v[0..n-1]: devolver -1 está correto.

O uso de invariantes para provar algoritmos, e a ligação com a indução, são explicados na página sobre o algoritmo de Euclides.

Análise

Contando as comparações feitas pelo laço:

  • Cada iteração faz DUAS comparações: o teste de fim (j < n) e o teste do elemento (v[j] == x).
  • Melhor caso: x está em v[0]. São 2 comparações: O(1).
  • Pior caso: x não está no vetor (ou está só na última posição). São n comparações com x e n + 1 testes de fim, ou seja, 2n + 1 comparações: O(n).
  • Caso médio: se x está no vetor, uma única vez, e todas as posições são igualmente prováveis, examinam-se em média (n + 1) / 2 elementos.

Não há como fazer melhor que O(n) no pior caso sem saber nada sobre a ordem dos dados: qualquer algoritmo que deixe de examinar uma posição pode errar quando x está justamente nela.

Busca com sentinela

O teste de fim (j < n) existe só para o laço não passar do fim do vetor quando x não está lá. A busca com sentinela elimina esse teste com um truque: antes de começar, coloca-se uma cópia de x numa posição extra, logo depois do último elemento, v[n]. Essa cópia é o sentinela: ela garante que o laço sempre encontra x e, portanto, sempre para.

  busca_sentinela(v, n, x):       (v precisa ter espaço para n + 1 elementos)
      v[n] <- x
      j <- 0
      enquanto v[j] != x: j <- j + 1
      se j < n: devolva j          (achou antes do sentinela)
      senão:    devolva -1         (só achou o sentinela)

O invariante é o mesmo (x não está em v[0..j-1]). A diferença está na contagem:

  • busca simples, pior caso: n comparações com x + (n + 1) testes de fim = 2n + 1;
  • busca com sentinela, pior caso: (n + 1) comparações com x + 1 teste no final = n + 2.

A ordem de crescimento continua O(n): o sentinela não muda a classe do algoritmo, mas corta quase pela metade o número de testes, o que se nota em laços executados milhões de vezes. Custos do truque: é preciso uma posição a mais no vetor, e a função escreve no vetor (não pode ser usada com um vetor somente leitura nem em dois processos que leem o mesmo vetor ao mesmo tempo).

A mesma ideia aparece em outros lugares: a inserção direta com sentinela em v[0] elimina o teste j >= 0, e a célula-cabeça das listas encadeadas elimina casos especiais.

Exemplo

Vetor v = (31, 7, 18, 42, 5, 26, 13, 9), com n = 8.

  procurar 26:  examina 31, 7, 18, 42, 5, 26        -> posição 5
                simples: 6 com x + 6 de fim = 12   sentinela: 6 + 1 = 7
  procurar 99:  examina os 8 elementos              -> -1
                simples: 8 com x + 9 de fim = 17   sentinela: 9 + 1 = 10

Quando usar a busca sequencial

  • O vetor não está ordenado e serão feitas poucas buscas. Ordenar custa O(n log n); só compensa se depois vierem muitas buscas binárias de O(log n) cada.
  • A estrutura só permite acesso em sequência, como uma lista encadeada ou um arquivo lido do começo ao fim.
  • O vetor é pequeno: para algumas dezenas de elementos, o laço simples costuma ser tão rápido quanto métodos mais sofisticados.
  • Quando há muitas buscas num conjunto que muda, a melhor opção costuma ser uma tabela de espalhamento, com busca em tempo médio O(1).

Uma variação útil é a busca auto-organizada: cada elemento encontrado é movido para o início (ou trocado com o anterior), de modo que os elementos procurados com frequência ficam perto do começo.

Histórico

A busca sequencial é tão antiga quanto as listas. Knuth a apresenta como o primeiro algoritmo de busca do volume 3 de "The Art of Computer Programming" (seção 6.1), junto com a versão com sentinela, e mostra que o sentinela torna o laço interno bem mais rápido nas máquinas da época.

Sobre o código

O programa implementa as duas buscas sobre o vetor do exemplo, procura um valor do meio, o primeiro e um ausente, e imprime a posição devolvida e o número de comparações de cada método.
