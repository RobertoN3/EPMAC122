7. Titulo: Estabilidade em algoritmos de ordenação

## Ideia geral

Um algoritmo de [[ordenacao|ordenação]] é estável quando preserva a ordem
relativa dos elementos cujas chaves de ordenação são iguais. Se Ana aparece
antes de Bruno na entrada e os dois têm nota 8, uma ordenação estável apenas
pela nota mantém Ana antes de Bruno.

Dois cuidados com a definição:
- a propriedade precisa valer para TODAS as entradas, não apenas para um
  exemplo; um teste que "deu certo" não prova estabilidade;
- estabilidade não significa deixar os elementos nas posições originais:
  eles podem mudar de lugar, desde que os empatados mantenham a ordem entre
  si.

A estabilidade só faz diferença quando ordenamos [[registros]] com mais de
um campo: ao ordenar números soltos, dois valores iguais são
indistinguíveis.

## Exemplo: estável x instável

Entrada, nesta ordem: Ana (nota 8), Bruno (nota 8), Carla (nota 6).
Ordenamos por nota crescente.

Com a [[insertionsort|inserção direta]], Bruno não ultrapassa Ana, pois as
notas são iguais e só se deslocam elementos ESTRITAMENTE maiores. Ao
inserir Carla, deslocamos Bruno e Ana uma posição para a direita e colocamos
Carla no início:

```
  Carla (6), Ana (8), Bruno (8)
```

Ana e Bruno mudaram de posição, mas Ana continua antes de Bruno.

Com a [[selecao_direta|seleção direta]] com trocas, o primeiro passo encontra
Carla como menor nota e a troca com Ana, que está na primeira posição:

```
  Carla (6), Bruno (8), Ana (8)
```

Os dois restantes já estão em ordem de nota e nada mais muda. Ana e Bruno
trocaram de ordem relativa: o método é instável.

Note que a seleção usa comparação estrita na busca do mínimo, o que mantém
o PRIMEIRO mínimo encontrado. Isso preserva a escolha entre mínimos
empatados, mas não impede que a troca distante leve outro elemento (aqui,
Ana) para depois de um igual a ele. A estabilidade exige olhar para toda a
movimentação dos elementos, não só para o critério de escolha.

## Para que serve: ordenar por várias chaves

A estabilidade é útil quando há chaves com prioridades diferentes. Para
listar alunos em ordem crescente de nota e, nos empates, em ordem
alfabética de nome:
1) ordene por nome;
2) depois ordene, com um método ESTÁVEL, por nota.
A segunda passagem preserva a ordem de nomes dentro de cada grupo de notas
iguais.

Com mais chaves, fazem-se as passagens da chave MENOS importante para a MAIS
importante. O material da disciplina dá dois exemplos dessa relação entre
chave primária e secundária: capítulos e seções de um livro, e os pares
(linha, coluna) de uma matriz guardada por linhas. Exemplo com pares
(primária, secundária):

```
  original:                 (3,6) (7,5) (3,5) (6,2) (9,1)
  pela secundária:          (9,1) (6,2) (7,5) (3,5) (3,6)
  depois, estável, pela
  primária:                 (3,5) (3,6) (6,2) (7,5) (9,1)
```

Os pares (3,5) e (3,6) empatam na primária e ficam na ordem da passagem
anterior. Atenção: a estabilidade sozinha não ordena pelos nomes (ou pela
chave secundária); ela apenas PRESERVA a ordem que já existia antes da
passagem.

O [[radixsort|Radix Sort]] LSD é exatamente esse procedimento aplicado aos
dígitos de um número, do menos para o mais significativo, e só funciona
porque cada passagem é estável.

## Quais métodos são estáveis

Nas implementações usuais:
- [[bubblesort|Bolha]]: estável, se troca apenas vizinhos com chaves
  ESTRITAMENTE fora de ordem (v[i] > v[i+1]).
- [[insertionsort|Inserção direta]]: estável, se desloca apenas chaves
  ESTRITAMENTE maiores que a inserida.
- [[mergesort|Merge Sort]]: estável, se em um empate na intercalação escolhe
  primeiro o elemento da metade ESQUERDA (comparação <=).
- [[radixsort|Radix Sort]] e Counting Sort: estáveis, se a distribuição
  percorre o vetor de trás para a frente (ou mantém a ordem de chegada nos
  baldes).
- [[selecao_direta|Seleção direta]] com trocas: instável.
- [[quicksort|Quicksort]] com partição no próprio vetor: instável.
- [[heapsort|Heapsort]]: instável.

A classificação depende da implementação, não só do nome do algoritmo:
trocar < por <= no lugar errado pode destruir a estabilidade, e existem
variantes estáveis de métodos que normalmente são instáveis.

## Como obter um resultado estável com um método instável

Há uma técnica geral: anexar a cada elemento seu índice na entrada e
comparar o par (chave, índice). Primeiro comparam-se as chaves; em caso de
empate, o menor índice vem antes. Como os índices são todos distintos, não
há mais empates, e os elementos de mesma chave saem obrigatoriamente na
ordem de entrada. Depois da ordenação, os índices são descartados. O custo é
O(n) de memória extra para guardar os índices.

Para a seleção direta especificamente, há outra saída: em vez da troca
distante, retirar o mínimo e DESLOCAR uma posição para a direita os
elementos entre a posição dele e o início do trecho. Essa variante é estável
e continua Theta(n²) em comparações, mas pode fazer Theta(n²) movimentações,
em vez de apenas O(n) trocas.

## Estabilidade não é eficiência

Inserção direta e seleção direta têm pior caso Theta(n²) e usam Theta(1) de
memória extra, mas se comportam de modo diferente nos empates. A inserção
ainda tem melhor caso Theta(n), enquanto a seleção faz Theta(n²) comparações
mesmo com a entrada já ordenada. Estabilidade e
[[eficiencia|eficiência]] são propriedades independentes, e é preciso
analisar cada uma.

## Sobre o código

O programa ordena duas cópias do mesmo vetor de registros (nome e nota),
comparando só a nota: uma com a inserção direta estável e outra com a
seleção direta com trocas. O nome serve para observar a ordem relativa de
Ana e Bruno, que empatam, nas duas saídas.

INICIO_CODIGO_C
#include <stdio.h>

typedef struct {
    char nome[32];
    int nota;
} Aluno;

/* Estavel: registros com nota igual nao sao deslocados pela chave. */
void insertion_sort(Aluno vetor[], size_t n)
{
    for (size_t i = 1; i < n; i++) {
        Aluno chave = vetor[i];
        size_t j = i;

        while (j > 0 && vetor[j - 1].nota > chave.nota) {
            vetor[j] = vetor[j - 1];
            j--;
        }
        vetor[j] = chave;
    }
}

/* Instavel: a troca distante pode inverter registros de notas iguais.
   Mesmo selecionar o primeiro minimo nao impede essa inversao. */
void selecao_direta(Aluno vetor[], size_t n)
{
    for (size_t i = 0; i < n; i++) {
        size_t menor = i;

        for (size_t j = i + 1; j < n; j++) {
            if (vetor[j].nota < vetor[menor].nota) {
                menor = j;
            }
        }
        if (menor != i) {
            Aluno auxiliar = vetor[i];
            vetor[i] = vetor[menor];
            vetor[menor] = auxiliar;
        }
    }
}

void imprimir(const char *titulo, const Aluno vetor[], size_t n)
{
    printf("%s\n", titulo);
    for (size_t i = 0; i < n; i++) {
        printf("  %s: nota %d\n", vetor[i].nome, vetor[i].nota);
    }
    printf("\n");
}

int main(void)
{
    const Aluno original[] = {
        {"Ana", 8},
        {"Bruno", 8},
        {"Carla", 6}
    };
    Aluno estavel[sizeof original / sizeof original[0]];
    Aluno instavel[sizeof original / sizeof original[0]];
    const size_t n = sizeof original / sizeof original[0];

    // As duas ordenacoes recebem a mesma sequencia inicial.
    for (size_t i = 0; i < n; i++) {
        estavel[i] = original[i];
        instavel[i] = original[i];
    }

    insertion_sort(estavel, n);
    selecao_direta(instavel, n);

    imprimir("Entrada original:", original, n);
    imprimir("Insertion Sort estavel, por nota crescente:", estavel, n);
    imprimir("Selecao Direta instavel, por nota crescente:", instavel, n);
    printf("Ana e Bruno empatam na nota. Observe a ordem dos nomes.\n");
    return 0;
}
