6. Problema: Dado um vetor de n elementos comparáveis, rearranjá-lo de modo que fique em ordem crescente
7. Titulo: Algoritmos de ordenação

## Ideia geral

Ordenar é rearranjar os elementos de um vetor v[0..n-1] de modo que
v[0] <= v[1] <= ... <= v[n-1]. É um dos problemas mais estudados da
computação, por três razões:

- é extremamente frequente: listas de contatos, resultados de busca,
  relatórios, índices de livros, bancos de dados;
- dados ordenados tornam outros problemas fáceis: busca binária, encontrar
  repetidos, intercalar listas, calcular a mediana, encontrar os k maiores;
- é um ótimo "laboratório" para estudar técnicas de projeto (guloso, divisão
  e conquista, distribuição) e de análise de algoritmos.

Durante décadas, estimou-se que uma parte considerável do tempo de
processamento dos computadores comerciais era gasta ordenando dados.

## Chaves e registros

Em geral não se ordenam números soltos, mas registros (structs) com vários
campos, usando um deles como chave de ordenação: alunos por número USP,
produtos por preço, arquivos por data. Os algoritmos são os mesmos; só a
comparação e a cópia mudam. Quando os registros são grandes, costuma-se
ordenar um vetor de ponteiros ou de índices, para não copiar registros
inteiros.

## Estabilidade

Um algoritmo de ordenação é estável se dois elementos com a mesma chave
aparecem, no vetor ordenado, na mesma ordem relativa em que estavam no vetor
original.

Por que isso importa? Quando os dados têm uma chave primária (mais
importante) e uma secundária (menos importante), é possível ordenar pelas
duas assim:
1) ordena-se primeiro pela chave secundária;
2) depois ordena-se, com um método ESTÁVEL, pela chave primária.
A segunda ordenação respeita a primeira entre os elementos empatados na
chave primária.

Exemplo com pares (primária, secundária):

  original:            (3,6) (7,5) (3,5) (6,2) (9,1)
  pela secundária:     (9,1) (6,2) (7,5) (3,5) (3,6)
  depois, estável,
  pela primária:       (3,5) (3,6) (6,2) (7,5) (9,1)

Os pares (3,5) e (3,6) empatam na chave primária e permanecem na ordem
obtida na etapa anterior, isto é, ordenados pela secundária. Usos práticos:
ordenar uma planilha por cidade e, dentro de cada cidade, por nome;
ordenar índices (linha, coluna) de uma matriz; e o próprio Radix Sort, que
ordena dígito a dígito, do menos para o mais significativo, e depende de cada
passada ser estável.

Qualquer algoritmo pode ser tornado estável acrescentando a posição original
como critério de desempate, ao custo de memória extra.

## Os principais métodos

Métodos elementares, O(n²):

- Bolha (bubble sort): troca vizinhos fora de ordem; cada passada leva o
  maior elemento restante para o fim. Estável. Faz muitas trocas.
  Pode ser vista como método guloso.
- Seleção direta (selection sort): a cada passo, seleciona o menor elemento
  restante e o troca com o primeiro da parte não ordenada. Faz sempre
  n(n-1)/2 comparações, mas apenas n-1 trocas. A versão com trocas NÃO é
  estável.
- Inserção direta (insertion sort): como quem organiza cartas na mão, insere
  cada novo elemento na posição correta entre os anteriores, já ordenados,
  deslocando os maiores para a direita. Estável. Muito rápida para vetores
  pequenos ou quase ordenados: o custo é O(n + número de inversões), e um
  vetor já ordenado custa O(n).

Métodos eficientes, O(n log n):

- Merge Sort (von Neumann, 1945): divisão e conquista; divide ao meio,
  ordena as metades recursivamente e intercala. O(n log n) em todos os
  casos, estável, mas usa O(n) de memória extra.
- Quick Sort (Hoare, 1959): divisão e conquista; escolhe um pivô e particiona
  o vetor em "menores" e "maiores" que ele, ordenando cada parte
  recursivamente. O(n log n) em média, mas O(n²) no pior caso (pivô sempre
  extremo, por exemplo com vetor já ordenado e pivô no início). Escolher o
  pivô ao acaso ou pela mediana de três torna o pior caso muito improvável.
  Em geral é o mais rápido na prática. Não é estável.
- Heap Sort (Williams, 1964): monta um heap (árvore binária guardada no
  vetor, em que cada pai é maior que os filhos) e retira repetidamente o
  máximo. O(n log n) no pior caso e memória O(1). Não é estável.

Métodos por distribuição (não comparam elementos entre si):

- Counting Sort: conta quantas vezes cada chave aparece; O(n + k) para chaves
  inteiras entre 0 e k-1.
- Radix Sort (Hollerith, 1887): ordena dígito a dígito, com um método estável
  (em geral, counting sort) em cada passada; O(d (n + k)) para chaves de d
  dígitos na base k.

Resumo:

  Algoritmo       Técnica              Pior caso    Médio       Memória  Estável
  Bolha           método guloso        O(n²)        O(n²)       O(1)     sim
  Seleção direta  método guloso        O(n²)        O(n²)       O(1)     não
  Inserção        incremental          O(n²)        O(n²)       O(1)     sim
  Merge Sort      divisão e conquista  O(n log n)   O(n log n)  O(n)     sim
  Quick Sort      divisão e conquista  O(n²)        O(n log n)  O(log n) não
  Heap Sort       seleção com heap     O(n log n)   O(n log n)  O(1)     não
  Radix Sort      distribuição         O(d(n+k))    O(d(n+k))   O(n+k)   sim

(A memória do Quick Sort é a da pilha de recursão, quando se ordena
recursivamente primeiro a parte menor.)

## Limite inferior para ordenação por comparação

Todo algoritmo que obtém informação sobre a ordem APENAS comparando pares de
elementos precisa, no pior caso, de pelo menos log2(n!) comparações, que é da
ordem de n log n.

O argumento usa uma árvore de decisão: cada nó interno é uma comparação
"v[i] < v[j]?", e cada folha corresponde a uma ordem final. Como há n!
ordens possíveis da entrada e cada uma precisa de uma folha diferente, a
árvore tem pelo menos n! folhas; uma árvore binária com n! folhas tem altura
pelo menos log2(n!), e log2(n!) ~ n log2 n - 1,44 n (fórmula de Stirling).

Consequências:
- Merge Sort e Heap Sort são assintoticamente ótimos entre os métodos por
  comparação;
- Counting Sort e Radix Sort escapam desse limite porque usam a estrutura
  das chaves (dígitos), e não só comparações.

## Na prática

- Para vetores pequenos (algumas dezenas de elementos) ou quase ordenados,
  a inserção direta é imbatível; por isso implementações profissionais usam
  inserção nos pedaços pequenos gerados pela recursão.
- A função qsort da biblioteca padrão do C ordena qualquer vetor recebendo
  uma função de comparação; o padrão não exige que ela seja estável.
- O std::sort de C++ costuma usar o Introsort (Musser, 1997): Quick Sort que
  troca para Heap Sort se a recursão ficar profunda demais, garantindo
  O(n log n).
- Python e Java (para objetos) usam o Timsort (Tim Peters, 2002), um
  Merge Sort adaptativo e estável, muito rápido em dados reais, que costumam
  ter trechos já ordenados.

INICIO_CODIGO_C
#include <stdio.h>

typedef struct {
  int primaria, secundaria;
} Par;

/* inserção direta por uma das chaves: é estável, pois só desloca
   elementos ESTRITAMENTE maiores que o elemento sendo inserido */
void insercao(Par v[], int n, int pelaPrimaria) {
  int i, j;
  Par x;
  for (i = 1; i < n; i++) {
    x = v[i];
    j = i - 1;
    while (j >= 0 && (pelaPrimaria ? v[j].primaria > x.primaria
                                   : v[j].secundaria > x.secundaria)) {
      v[j + 1] = v[j];
      j--;
    }
    v[j + 1] = x;
  }
}

void imprime(const char *rotulo, Par v[], int n) {
  int i;
  printf("%s: ", rotulo);
  for (i = 0; i < n; i++) printf("(%d,%d) ", v[i].primaria, v[i].secundaria);
  printf("\n");
}

int main(void) {
  Par v[] = {{3,6}, {7,5}, {3,5}, {6,2}, {9,1}};
  int n = 5;
  imprime("L1", v, n);
  insercao(v, n, 0);   // primeiro pela chave secundária
  imprime("L2", v, n);
  insercao(v, n, 1);   // depois, de forma estável, pela primária
  imprime("L3", v, n);
  return 0;
}
