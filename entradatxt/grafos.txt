## Ideia geral

Um grafo é uma estrutura matemática que representa objetos e as ligações
entre eles. Formalmente, um grafo G = (V, A) é formado por:
- um conjunto V de vértices (ou nós);
- um conjunto A de arestas; cada aresta liga um par de vértices.

Costuma-se escrever n = |V| para o número de vértices e m = |A| para o número
de arestas.

Grafos estão em toda parte:
- mapas: cidades são vértices e estradas são arestas (com o comprimento
  como peso);
- redes de computadores e a própria Internet;
- a Web: páginas são vértices e links são arcos;
- redes sociais: pessoas e amizades;
- dependências entre tarefas, disciplinas com pré-requisitos, módulos de um
  programa;
- moléculas (átomos e ligações), circuitos elétricos, redes de metrô.

Modelar um problema como grafo permite usar algoritmos gerais, já estudados
e provados corretos, em vez de inventar uma solução específica.

## Terminologia básica

- Grafo não dirigido: a aresta u-v não tem sentido; vale nos dois.
- Grafo dirigido (digrafo): cada arco u->v tem sentido, de u para v. Uma
  rua de mão única ou um link de uma página para outra são arcos.
- Grafo com pesos (ou custos): cada aresta tem um número associado
  (distância, tempo, preço, capacidade).
- Vizinhos (adjacentes): dois vértices ligados por uma aresta.
- Grau de um vértice: número de arestas que incidem nele. Em todo grafo, a
  soma dos graus é 2m, pois cada aresta contribui para o grau de dois
  vértices. Em digrafos distinguem-se grau de entrada e grau de saída.
- Passeio e caminho: um passeio é uma sequência de vértices v0, v1, ..., vk
  em que cada par consecutivo é ligado por uma aresta (em digrafos,
  respeitando o sentido). O comprimento é o número de arestas (k), ou a
  soma dos pesos, se houver pesos. Um caminho é um passeio que não repete
  vértices (muitos livros dizem "caminho simples").
- Ciclo: passeio com pelo menos uma aresta que começa e termina no mesmo
  vértice e não repete arestas nem os demais vértices.
- Grafo conexo: existe caminho entre quaisquer dois vértices. As
  componentes conexas são os "pedaços" conexos maximais de um grafo: não se
  pode acrescentar a eles nenhum outro vértice mantendo a conexidade. Um
  vértice isolado é, sozinho, uma componente. Em um digrafo, uma componente
  fortemente conexa é um conjunto maximal de vértices em que cada um alcança
  qualquer outro por um caminho dirigido.
- Subgrafo: grafo formado por parte dos vértices e arestas de G.
- Grafo completo: todos os pares de vértices são adjacentes; tem
  n(n-1)/2 arestas.
- Grafo esparso: m é da ordem de n (como em mapas de estradas). Grafo
  denso: m é da ordem de n².
- Grafo bipartido: os vértices se dividem em dois grupos e toda aresta liga
  um grupo ao outro (por exemplo, alunos e disciplinas).
- [[arvores|Árvore]]: grafo conexo e sem ciclos. Tem exatamente n-1 arestas.
  Uma floresta é um grafo sem ciclos (cada componente é uma árvore).
- Árvore espalhada (geradora) de G: subgrafo de G que é árvore e contém
  todos os vértices. Se há pesos, a de menor peso total é a árvore
  espalhada mínima.

## Representações no computador

1) Matriz de adjacência: uma matriz n x n em que adj[u][v] = 1 (ou o peso da
   aresta) se existe a aresta u-v, e 0 caso contrário. Para grafos não
   dirigidos a matriz é simétrica.
   - testar se u-v é aresta: O(1);
   - percorrer os vizinhos de u: O(n), mesmo que u tenha poucos vizinhos;
   - memória: O(n²). Boa para grafos densos ou pequenos.

2) Listas de adjacência: um vetor de n [[listas_encadeadas|listas encadeadas]];
   a lista do vértice u contém seus vizinhos (e os pesos, se houver).
   - testar se u-v é aresta: O(grau(u));
   - percorrer os vizinhos de u: O(grau(u));
   - memória: O(n + m). Boa para grafos esparsos, que são a maioria dos
     grafos grandes na prática (um mapa com milhões de cruzamentos tem
     poucas ruas por cruzamento).

3) Lista de arestas: um vetor com os m pares (u, v, peso). Simples e útil
   quando o algoritmo processa as arestas em ordem, como o de
   [[kruskal|Kruskal]].

4) Matriz de incidência (apresentada no material da disciplina): as linhas
   representam vértices e as colunas representam arestas. Em um grafo não
   dirigido, a coluna de uma aresta marca com 1 as suas duas extremidades;
   em um digrafo, pode-se usar -1 na origem e 1 no destino. Ocupa
   O(n · m) de memória e é mais usada em teoria (por exemplo, em fluxos e
   circuitos elétricos) do que em algoritmos.

Exemplo do material da disciplina, o grafo G1: V = {1, 2, 3, 4} e
A = {1-2, 1-3, 1-4, 3-4}. Cada aresta não dirigida entra duas vezes na
matriz de adjacência (posições [1][2] e [2][1], por exemplo) e nas listas de
suas duas extremidades. Os graus ficam 3, 1, 2 e 2; a soma 8 é o dobro do
número de arestas, como manda a propriedade dos graus.

Exemplo: o grafo não dirigido com vértices 0 a 4 e arestas 0-1, 0-2, 1-3,
2-3 e 3-4 fica assim nas duas representações principais:

```
  matriz de adjacência        listas de adjacência
      0 1 2 3 4
  0:  0 1 1 0 0               0: 2 -> 1
  1:  1 0 0 1 0               1: 3 -> 0
  2:  1 0 0 1 0               2: 3 -> 0
  3:  0 1 1 0 1               3: 4 -> 2 -> 1
  4:  0 0 0 1 0               4: 3
```

Nas listas, cada vizinho novo é inserido no início da lista (custo O(1)),
por isso os vizinhos aparecem na ordem inversa da inserção.

## Percorrendo um grafo

Quase todo algoritmo em grafos começa por um percurso sistemático, que
visita cada vértice alcançável uma única vez. Os dois percursos básicos
diferem apenas na estrutura que guarda os vértices "a visitar":

- Busca em largura ([[bfs|BFS]]): usa uma [[filas|fila]]. Visita os vértices
  em "ondas" a partir da origem e, por isso, calcula o menor número de
  arestas da origem a cada vértice. Tem página própria.
- Busca em profundidade (DFS): usa uma [[pilhas|pilha]], ou, de forma
  equivalente, a [[recursao|recursão]]. Segue um caminho o mais longe
  possível; quando chega a um vértice sem vizinhos novos, volta (como no
  [[tentativa_erro|backtracking]]) e tenta outro ramo:

```
  dfs(u):
      marque u como visitado
      para cada vizinho v de u:
          se v não foi visitado: dfs(v)
```

As duas custam O(n + m) com listas de adjacência e O(n²) com matriz.
Aplicações da DFS: encontrar componentes conexas, detectar ciclos,
[[ordenacao_topologica|ordenação topológica]] (ordem para executar tarefas
com dependências), encontrar pontes e pontos de articulação, resolver
labirintos.

## Problemas clássicos em grafos

- Árvore espalhada mínima: ligar todos os vértices com o menor custo
  (algoritmos de [[kruskal|Kruskal]] e de [[prim|Prim]];
  [[metodo_guloso|método guloso]]).
- Caminhos mínimos com pesos: algoritmo de [[dijkstra|Dijkstra]] (pesos não
  negativos, guloso), Bellman-Ford e Floyd-Warshall
  ([[programacao_dinamica|programação dinâmica]]).
- [[ordenacao_topologica|Ordenação topológica]]: dispor os vértices de um
  grafo dirigido de modo que toda aresta vá de um vértice anterior para um
  posterior. Existe exatamente quando o grafo não tem ciclos dirigidos.
- Coloração: atribuir cores aos vértices de modo que vizinhos tenham cores
  diferentes (alocação de horários, de registradores, de frequências). O
  Teorema das Quatro Cores (1976) garante que todo mapa plano pode ser
  colorido com 4 cores.
- Circuito euleriano: percorre cada ARESTA exatamente uma vez e volta ao
  início, podendo repetir vértices. É fácil: em um grafo conexo, existe se e
  somente se todos os graus são pares. Circuito hamiltoniano: visita cada
  VÉRTICE exatamente uma vez antes de voltar ao inicial. Parece parecido,
  mas decidir se existe é NP-completo, assim como o problema do
  caixeiro-viajante.
- Fluxo máximo e emparelhamentos.

## Histórico: as pontes de Königsberg

A teoria dos grafos nasceu de um quebra-cabeça. A cidade de Königsberg
(hoje Kaliningrado, na Rússia) era cortada pelo rio Pregel, com duas ilhas
ligadas às margens e entre si por sete pontes. Os moradores perguntavam se
seria possível passear pela cidade atravessando cada ponte exatamente uma
vez.

Em 1736, Leonhard Euler resolveu o problema abstraindo os detalhes: cada
porção de terra virou um ponto (vértice) e cada ponte, uma linha (aresta).
Ele observou que, em um passeio desse tipo, toda vez que se chega a uma
região por uma ponte, sai-se por outra; assim, exceto pelo início e pelo
fim, toda região precisa ter um número PAR de pontes. Em Königsberg, as
quatro regiões tinham número ímpar de pontes, e o passeio era impossível.
O artigo foi publicado em 1741.

A palavra "graph" foi usada nesse sentido por J. J. Sylvester em 1878, e o
primeiro livro sobre o assunto foi escrito por Dénes König em 1936. A busca
em profundidade foi estudada já no século XIX por Charles Trémaux, como
método para explorar labirintos, e sistematizada por Hopcroft e Tarjan
(1973).

## Sobre o código

O programa de exemplo monta o mesmo grafo do exemplo acima nas duas
representações: uma matriz de adjacência (vetor de vetores) e um vetor de
listas de adjacência ([[registros]] ligados por [[ponteiros]], alocados com malloc).
Em seguida imprime as duas e libera a memória das listas. Os percursos estão
nas páginas [[bfs]] e [[dijkstra]].

INICIO_CODIGO_C
#include <stdio.h>
#include <stdlib.h>
#define MAXV 8

/* Representação 1: matriz de adjacência */
int adj[MAXV][MAXV];

/* Representação 2: vetor de listas de adjacência */
typedef struct no {
  int vizinho;
  struct no *prox;
} No;

No *lista[MAXV];
int nv = 5;                     /* número de vértices */

/* insere v no início da lista de u: custo O(1) */
void insere_lista(int u, int v) {
  No *novo = malloc(sizeof(No));
  if (novo == NULL) exit(1);
  novo->vizinho = v;
  novo->prox = lista[u];
  lista[u] = novo;
}

/* grafo não dirigido: a aresta u-v vale nos dois sentidos */
void aresta(int u, int v) {
  adj[u][v] = adj[v][u] = 1;
  insere_lista(u, v);
  insere_lista(v, u);
}

int main(void) {
  int u, v;
  No *p, *q;
  aresta(0, 1); aresta(0, 2); aresta(1, 3);
  aresta(2, 3); aresta(3, 4);

  printf("Matriz de adjacencia:\n");
  for (u = 0; u < nv; u++) {
    for (v = 0; v < nv; v++) printf("%d ", adj[u][v]);
    printf("\n");
  }

  printf("Listas de adjacencia:\n");
  for (u = 0; u < nv; u++) {
    printf("%d:", u);
    for (p = lista[u]; p != NULL; p = p->prox)   // percorre os vizinhos
      printf(" %d", p->vizinho);
    printf("\n");
  }

  for (u = 0; u < nv; u++)                       /* libera as listas */
    for (p = lista[u]; p != NULL; p = q) {
      q = p->prox;
      free(p);
    }
  return 0;
}
FIM_CODIGO_C
